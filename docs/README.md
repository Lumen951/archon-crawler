## 文档状态

- **当前实现基线**：已由代码、配置或测试核对，可作为开发上下文；若实现变化应同步更新。
- **已确认规格**：产品意图已经明确，变更需要先更新规格再改代码。
- **待确认**：旧资料或讨论中出现，但范围、优先级或验收条件尚未得到确认；不能当作承诺。
- **历史资料**：为排查兼容性保留，不代表当前默认行为。

## 维护规则

1. 代码变更影响用户行为、任务状态、外部依赖或安全边界时，检查对应领域文档和架构文档。
2. 规格与代码有差异时，记录“规格意图 / 当前实现 / 建议”，由人决定是否反向更新规格。
3. 并行演进的独立改动可在领域目录下使用 Patch；Patch 必须说明替代范围，并与主文档双向链接。
4. 功能下线先写日落说明和迁移影响，保留必要历史上下文，再删除代码或文档。
5. 不把真实凭据、生产数据、Cookie、Token 或本地服务器访问信息写入版本库。

## 当前已实现能力概览

- 多平台账号与文章采集：微信公众号、小红书、Twitter/X、官网；账号采用 STI，抓取由统一编排器调度。
- 抓取任务：异步 Job、账号级状态、暂停/恢复、错误阈值、结构化日志、活跃度分层与到期调度。
- 官网监测：站点发现、列表规则、页面版本、变化检测、文章同步和监测 RSS。
- 活动研究：活动配置、单个/批量研究、缓存、外部检索与企业信息、研究运行记录、周报和可选飞书推送。
- 交付与协作：网页管理端、标签和分组、RSS、ApiKey 保护的 REST API、带 OAuth 2.1 的 MCP 服务。

以上是仓库当前实现的摘要，不等于未列出的产品路线图。

## 当前项目理解

本次核对基于 `codex/archon-branding-auth` 的 `1c37c9c`：这个版本包含 Archon 品牌和开发者登录改动。核对时 `origin/main` 为 `a4757d7`，两者的登录/seed 行为不同；不能把本文关于开发者账号的描述套用于尚未合并品牌改动的 main。此处保留核对基点，后续改变相关行为时应更新。

平台的主要工作分为内容采集和活动研究。前者沉淀文章及网站变化，后者沉淀带证据的结构化研究结果；账号、标签、用户和外部访问入口构成共享基础设施。当前已有管理界面、任务进度与日志、报告和对外查询入口，项目已超出单纯 RSS 爬虫的范围。

“已有实现”不代表线上已启用，也不代表本轮运行了全部测试。配置、外部会话、队列和部署版本会影响实际可用性。当前手动 CI、未自动强制的文档规则、遗留专题资料都应在使用时明确区分。

## 谁维护、什么时候维护

| 发生的变化 | 提交者需要更新 | 审阅者需要检查 |
|---|---|---|
| 新增或改变用户行为 | 对应 specs，必要时 README 能力摘要 | 范围、权限、失败路径和验收条件 |
| 改模型、Job、外部依赖 | architecture 及相关 specs | 调用关系、状态和数据来源是否一致 |
| 发现可复用的故障经验 | runbook 的排错与注意事项 | 是否有证据、是否泄露运行数据 |
| 重要行为或协作决策 | changelog，链接生效文档 | 决策是否经确认、是否遗漏迁移影响 |
| 仅修正文案或链接 | 相应文档 | 不必制造无意义的变更记录 |

尚无固定模块负责人名单，暂由变更提交者维护、PR 审阅者验收；不能虚构负责人。多人并行前声明负责的页面/路由、后端领域、共享模型和 spec 范围，触及交叉边界时先对齐。该流程是约定，没有新增 hook、自动化 Skill 或 CI 门禁。

## 与参考实践的取舍

本轮采用《天猫技术大型 AI 项目的研发协同实践》的入口地图、规格生命周期、提交时知识核对与外部上下文补充思路。文章是方法参考，不是本仓库运行指令。

先维护 specs、architecture、runbook、changelog 四类实际内容；wiki 和 vendor 按后续调研/参考源码需要再审批创建。不引入六个 Skill、多仓库聚合、哨兵机或云端协作平台。外部素材需记录来源和版本，不能未经阅读就当作本项目规则。

[mcp.md](mcp.md) 与 [tianyancha_api.md](tianyancha_api.md) 保留原路径和正文；本次没有逐项验证其中全部接入示例。遇到专题资料与当前源码不一致时先列出差异，不据旧说明修改系统行为。
